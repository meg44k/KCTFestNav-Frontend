# 写真のアップロード 設計

- 作成日: 2026-10-09
- 対象リポジトリ: KCTFestNav-Backend(画像を受け取って置く API・古い画像の削除・手元の保存先)、KCTFestNav-Frontend(写真を選ぶ部品・3 か所の差し替え・表示)
- 期限: 高専祭(2026-10-31〜11-01)の 1 週間前、10/24 まで

## 1. 目的

今は画像を「URL を入力する」方式で、分かりにくい。スマホで撮った写真をそのまま選んで使えるようにする。

成功の基準:
- 企画担当・管理者がブースの写真を、管理者が出演者の写真を、「写真を選ぶ」から上げられる。スマホのカメラ・写真ライブラリから選べる
- 選んだ写真は自動で中心を正方形に切り抜いて軽くしてから送られ、上げる前にカードでの見え方が分かる
- 来場者の画面(一覧のカード・詳細・ステージ)に写真が出る

## 2. 決定事項(本人と合意済み 2026-10-09)

- 対象: ブースの画像(企画担当・管理者)、ステージの出演者のサムネイル
- 切り抜きは自動。写真の中心を正方形に切り抜く。カードも詳細も正方形で出す(今の詳細の 16:9 は正方形にそろえる)
- URL を入力する欄は消す
- 仕組みは「バックエンドが受け取って R2 に置く」(案 A)。R2 の鍵と権限の確認をバックエンド 1 か所にまとめる
- 写真を差し替えたら古い写真を R2 から消す。アップロードして保存しなかった写真は残ってよい(掃除しない)

## 3. しくみ

```
ブラウザ: 写真を選ぶ → 中心を正方形に切り抜き 1080×1080 に縮める(WebP、作れなければ JPEG)
   ↓ Server Action(ログインの JWT)
Next.js のサーバー → POST /manage/images(multipart: file・target)
   ↓
Go: 権限 → 中身の確認 → 保存(本番は R2、手元はフォルダ)→ { url }
   ↓
フォームの隠し欄に URL → 「保存」で今までのブース・出演者の更新に入る
```

## 4. バックエンド

### 4.1 API

`POST /manage/images`(JWT。multipart)

| 項目 | 中身 |
|---|---|
| `file` | 画像。JPEG・PNG・WebP、2MB まで。中身を `http.DetectContentType` で確かめる |
| `target` | `booth:<ID>` か `performer:<ID>` |

- 権限は「その物を更新できる人」と同じ: ブースは Admin・Gakuseikai・その担当の Student、出演者は Admin(今の `UpdatePerformer` と同じ)
- 応答 `201 { "url": "https://img.kctfes.app/booths/3/<UUID>.webp" }`
- 形式・大きさ・target が違えば 400、権限が無ければ 403、ブース・出演者が無ければ 404
- 置き場所の名前: `booths/<ID>/<UUID>.<拡張子>`、`performers/<ID>/<UUID>.<拡張子>`

### 4.2 古い写真を消す

- ブースの更新(`BoothUsecase.Update`)・出演者の更新(`UpdatePerformer`)で、画像の URL が変わり、前の URL が自分の置き場所(`IMAGE_BASE_URL` で始まる)なら、更新のあとで前の画像を消す
- 消すのに失敗しても更新は成功にする(ログだけ)

### 4.3 置き場所

- 本番: R2(S3 互換。`aws-sdk-go-v2`)。環境変数 `R2_ACCOUNT_ID`・`R2_BUCKET`・`R2_ACCESS_KEY_ID`・`R2_SECRET_ACCESS_KEY`、配る URL の頭 `IMAGE_BASE_URL=https://img.kctfes.app`
- 手元: `R2_BUCKET` が無いときはフォルダ `UPLOAD_DIR`(既定 `./uploads`、git に入れない)に置き、バックエンドが `/images/*` で配る。`IMAGE_BASE_URL` の既定は `https://localhost:3000/dev-images`(開発のフロントは https なので、Next.js の開発サーバーが `/dev-images/*` をバックエンドの `/images/*` に中継する)
- R2 の鍵は本人が Cloudflare の画面で作り(権限: そのバケットの読み書き)、Secret Manager に入れる。`R2_ACCOUNT_ID`・`R2_BUCKET`・`IMAGE_BASE_URL` は Terraform で Cloud Run に渡す

## 5. フロント

### 5.1 写真を選ぶ部品(`ImagePicker`)

```
┌─────────┐
│ プレビュー │  ← カードと同じ正方形
└─────────┘
[写真を選ぶ]  [外す]
```

- `<input type="file" accept="image/*">`(スマホはカメラ・写真ライブラリ)
- 選んだら、中心の正方形を切り抜いて 1080×1080(元が小さければそのまま)にし、WebP で作る(作れないブラウザは JPEG・品質 0.85)。2MB を超えたら品質を下げてやり直す
- すぐ `uploadImage` でアップロードし、返った URL をプレビューと隠し欄(`name` はそれぞれ今の `imageUrl` / `thumbnailUrl`)に入れる
- アップロード中は「アップロード中…」、失敗は短い文言(形式が違う・大きすぎる・権限が無い・つながらない)
- 「外す」で隠し欄を空にする(保存すると画像なし)

### 5.2 差し替える場所

- 企画担当「ブースの説明」(`DetailForm`)— 今の確認ダイアログ(来場者全員に見られる)はそのまま
- 管理者「ブース管理」(`BoothFormDialog`)— 新規作成のときはブースの ID がまだ無いので、写真は作ったあとの編集で上げる(新規の画面では「保存してから写真を追加できます」と出す)
- 「ライブの編集」の出演者(`StageEditor`)— 新規の出演者も同じく、作ったあとに上げる
- URL の入力欄は全部消す。今のフォームの URL の検証(`https?://`)は、隠し欄の値に対してそのまま使う

### 5.3 表示

- ブースの詳細も正方形にする
- `next/image` は `unoptimized`(もう縮めてあるので、Vercel の画像変換の無料枠を使わない。外のサイトの画像の設定も要らなくなる)

## 6. テスト

- バックエンド: target の読み方、形式・大きさの確認、権限(Student は自分のブースだけ、出演者は Admin だけ)、手元の置き場所に書いて読める・消せる、更新で古い画像を消す(自分の置き場所の URL だけ)、e2e(multipart で上げて URL が返り、その URL で取れる)
- フロント: 切り抜きの計算(横長・縦長・正方形・小さい写真)、`uploadImage`(multipart で送る・失敗の文言)、フォームの検証
- 実機: Playwright(390px)で 3 か所とも写真を選んで保存 → 来場者の画面に出る

## 7. 進め方

1. バックエンド: target・確認・置き場所(フォルダと R2)・API・古い画像の削除・設定と Terraform → PR
2. フロント: 切り抜き・アップロードの action・`ImagePicker`・3 か所の差し替え・表示・開発の中継 → PR
3. 本番は「まとめて反映」のときに: R2 の鍵を作る → Secret Manager → terraform apply → develop を main へ
