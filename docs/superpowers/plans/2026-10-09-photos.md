# 写真のアップロード Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** ブースの写真(企画担当・管理者)と出演者の写真(管理者)を、URL の入力ではなく「写真を選ぶ」で上げられるようにする。

**Architecture:** ブラウザで中心を正方形に切り抜いて 1080px の WebP/JPEG にし、Server Action が JWT 付きでバックエンドの `POST /manage/images` に multipart で送る。Go は権限・中身を確かめて `ImageStore`(本番 R2、手元はフォルダ)に置き、URL を返す。フォームは隠し欄に URL を持ち、今までの更新で保存する。更新で画像が変わったら古い画像を消す。

**Tech Stack:** Go 1.25 / Echo v5 / aws-sdk-go-v2(S3 互換で R2)、Next.js 16 / Server Actions / Canvas、vitest、Terraform

**Spec:** `docs/superpowers/specs/2026-10-09-photos-design.md`(KCTFestNav-Frontend)

## Global Constraints

- 受け付ける形式は JPEG・PNG・WebP、2MB まで。中身は `http.DetectContentType` で確かめる
- target は `booth:<ID>` / `performer:<ID>`。権限は更新と同じ(ブース: Admin・Gakuseikai・担当の Student、出演者: Admin)
- 置き場所の名前 `booths/<ID>/<UUID>.<ext>`・`performers/<ID>/<UUID>.<ext>`
- 本番 R2(`R2_ACCOUNT_ID`・`R2_BUCKET`・`R2_ACCESS_KEY_ID`・`R2_SECRET_ACCESS_KEY`)、`IMAGE_BASE_URL=https://img.kctfes.app`。`R2_BUCKET` が無ければフォルダ `UPLOAD_DIR`(既定 `./uploads`)に置き `/images/*` で配る。`IMAGE_BASE_URL` の既定は `https://localhost:3000/dev-images`
- 切り抜きは中心の正方形、長辺 1080px まで、WebP(作れなければ JPEG 0.85)
- 表示は正方形、`next/image` は `unoptimized`
- 本人のサーバー(:1323・:3000)と開発 DB は触らない。PR のあとも作業フォルダは feature ブランチのままにする(本人が手元で見られるように)

## Review Focus

1. **権限のすり抜け**: Student が他のブースの target で上げる、Gakuseikai が出演者に上げる → 403(Task 3)
2. **形式の偽装**: 拡張子や Content-Type ヘッダーだけ画像で中身が違うもの、2MB を超えるもの → 400(Task 1・4)
3. **古い画像の削除**: 外の URL や空から変えたときは何も消さない。自分の置き場所の URL だけ消す。消すのに失敗しても更新は成功(Task 3)
4. **切り抜きの計算**: 横長・縦長・小さい写真で中心の正方形が正しい(Task 6)
5. **新規作成のとき**: まだ ID が無いので写真の部品を出さず案内を出す(Task 8)
