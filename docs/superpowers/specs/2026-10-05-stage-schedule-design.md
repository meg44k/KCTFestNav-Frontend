# ステージイベント（セクション・ブロック・出演者） 設計

- 作成日: 2026-10-05
- 対象リポジトリ: KCTFestNav-Backend（データの形・API の作り替え）、KCTFestNav-Frontend（来場者画面・管理画面）
- 期限: 高専祭（2026-10-31〜11-01）の 1 週間前、10/24 まで

## 1. 目的

各日のステージは「セクション」に分かれ、セクションの中に「ブロック」、ブロックの中に複数の出演者（バンド・ミュージシャン）がいる。

- 例: 「Live1」= 8 バンド（ブロック 1 つ）
- 例: 「癒し系ミュージシャン」= n ブロック × m 組

今の「ライブ」は 1 件ずつの平たい形（名前・時刻・回数・状態）で、この構造を表せない。データの形から作り替え、来場者が「今だれが演奏中か・次はだれか・この後の流れ」を一画面で分かるようにする。

成功の基準:
- 来場者がステージイベントを開くと、演奏中の出演者と次の出演者がすぐ分かる
- 学生会がスマホで **1 タップ**（「次のバンドへ」）で演奏中の出演者を進められる
- 押し忘れても、ブロックの時間を過ぎれば「演奏中」は自動で消える

## 2. 決定事項（本人と合意済み）

- 時刻はセクション・ブロック単位で決まっている。出演者ごとの時刻は**持たない**（順番だけ）
- 演奏中の出演者は**学生会が手動で進める**（管理画面の「次のバンドへ」「前に戻す」）
- 来場者画面は「案 1: タイムテーブル＋上部の『演奏中』の帯」
- セクションに**場所**（自由入力の文字列。例「第一体育館」）を持たせる。複数会場の同時進行にデータの上では対応するが、場所ごとのタブや絞り込みは作らない
- 今の `lives` テーブルと `/lives` API、「回数」「状態」は**なくして置き換える**。互換は保たない（本番データはまだ無い）
- バックエンド PR #24（旧形式のライブのモック）は不要になる。新しい形のモックに作り直す

## 3. データの形（バックエンド）

```
stage_sections  セクション
  id, name, location, sort_order
stage_blocks    ブロック
  id, section_id → stage_sections(ON DELETE CASCADE),
  start_time, end_time (DATETIME, UTC),
  current_order (INT, 0 = まだ始まっていない)
performers      出演者
  id, block_id → stage_blocks(ON DELETE CASCADE),
  name, detail, thumbnail_url, perform_order
```

- `name` は必須。`location`・`detail`・`thumbnail_url` は空でよい
- 日付・セクションの時間帯は持たず、ブロックから求める（日付 = ブロック開始時刻の JST の日、セクションの時間帯 = 中のブロックの最初の開始〜最後の終了）
- ブロックは `start_time` の順、出演者は `perform_order` の順、セクションは `sort_order`（同じなら最初のブロックの開始時刻）の順に並べる
- `end_time` は `start_time` より後でなければならない
- セクションがブロックを複数の日にまたいで持つことは想定しない（日付タブは各ブロックの日付で振り分けるので、またいでも壊れはしない）

### 演奏中の決まり方

ブロックの `current_order` は「何組目まで進んだか」。

| current_order | 意味 |
|---|---|
| 0 | まだ始まっていない |
| 1〜出演者数 | その順番の出演者が演奏中 |
| 出演者数 + 1 | ブロックは終了 |

- 「次のバンドへ」で +1（上限 出演者数 + 1）、「前に戻す」で −1（下限 0）。上限・下限で押しても値は変わらず、エラーにもしない
- **来場者に「演奏中」と出すのは、現在時刻がブロックの `start_time`〜`end_time` の間にあり、かつ 1 ≦ current_order ≦ 出演者数 のときだけ**。時間外なら current_order に関係なく演奏中は出さない
- 判定はバックエンドが行い、応答に `now_playing` として入れる（端末の時計のずれに左右されない）
- 出演者を削除・並べ替えしても current_order はそのまま（運営が「前に戻す」で直す）

## 4. API

### 来場者向け（認証なし）

`GET /stage` — 全部をまとめて返す。

```json
{
  "sections": [
    {
      "id": 1, "name": "Live1", "location": "第一体育館", "sort_order": 1,
      "blocks": [
        {
          "id": 1,
          "start_time": "2026-10-31T13:00:00+09:00",
          "end_time": "2026-10-31T13:50:00+09:00",
          "current_order": 2,
          "now_playing": true,
          "performers": [
            { "id": 1, "name": "バンドA", "detail": "...", "thumbnail_url": "", "perform_order": 1 }
          ]
        }
      ]
    }
  ]
}
```

- `now_playing`: §3 の条件を満たすとき true。演奏中の出演者は `performers` の中で `perform_order == current_order` のもの
- 時刻は +09:00 で返す

### 学生会・管理者（Admin, Gakuseikai）

- `POST /manage/stage/blocks/:id/next` — current_order を 1 進める。更新後のブロックを返す
- `POST /manage/stage/blocks/:id/prev` — current_order を 1 戻す。更新後のブロックを返す

### 管理者のみ（Admin）

- セクション: `POST /manage/stage/sections`、`PUT /manage/stage/sections/:id`、`DELETE /manage/stage/sections/:id`
- ブロック: `POST /manage/stage/sections/:id/blocks`、`PUT /manage/stage/blocks/:id`、`DELETE /manage/stage/blocks/:id`
- 出演者: `POST /manage/stage/blocks/:id/performers`、`PUT /manage/stage/performers/:id`、`DELETE /manage/stage/performers/:id`
- 出演順の入れ替え: `POST /manage/stage/performers/:id/move`（`{"direction": "up" | "down"}`。隣と perform_order を入れ替える。端なら何もしない）
- 出演者の追加時は perform_order = そのブロックの最大 + 1

エラー: 入力不正は 400、存在しない id は 404、権限なしは 403（既存の handler.go の対応表に合わせる）。

### なくすもの

`GET /lives`、`GET /lives/:id`、`GET /lives/current`、`/manage/lives` 一式、`lives` テーブル、Redis の `lives:current`。

## 5. 来場者画面（/stage-event）

```
ステージイベント
[10/31(土)] [11/1(日)]          ← 日付タブ。今日があれば今日、無ければ最初の日
┌ 演奏中 ─────────────┐
│ Live1 ・第一体育館          │
│ バンドB                     │
│ 次: バンドC                 │
└─────────────────┘
Live1  第一体育館  13:00〜13:50
  ✓ バンドA
  ▶ バンドB   演奏中
    バンドC
癒し系ミュージシャン  中庭  14:00〜15:30
  ブロック1  14:00〜14:40
    奏者X / 奏者Y / 奏者Z
  ブロック2  14:50〜15:30
    ...
```

- **演奏中の帯**: 選んだ日の `now_playing` のブロックを全部並べる（ふつうは 1 つ）。セクション名・場所・演奏中の出演者・次の出演者（最後なら「このブロックの最後です」）。無ければ帯は出さず、その日の次に始まるブロックを「次は 14:00〜 癒し系ミュージシャン」と出す。その日にもう何も無ければ何も出さない
- **セクション**: 見出しに名前・場所・時間帯。ブロックが 1 つだけなら「ブロック1」の見出しは出さず出演者を直接並べる
- **出演者の印**: current_order より前（current_order が出演者数を超えていれば全員）は ✓（終わった）。current_order の出演者は、`now_playing` のときだけ ▶ と「演奏中」（時間外は印なし。§3 の「時間外は演奏中を出さない」に合わせる）。それ以外は印なし
- **終わったセクション**（全ブロックの end_time が過ぎた）は小さくたたみ、タップで開く
- 出演者をタップすると今のダイアログ（LiveScheduleCard の詳細）を流用して紹介文・写真を出す。見出しは「バンド紹介」ではなく出演者名
- 60 秒ごとに自動更新（RefreshEvery）。日付タブは URL（`?day=2026-11-01`）に残す
- 読み込みに失敗したら既存と同じ文言で知らせる。セクションが 1 つも無ければ「ステージイベントの予定はまだありません。」

## 6. 管理画面

### 学生会・管理者: 「ライブ」ページ（/manage/ops/lives）を作り替え

```
ライブ                         [10/31] [11/1]
───────────────────────
Live1 ・第一体育館  13:00〜13:50   (時間内なら開いた状態)
 ✓ バンドA
 ▶ バンドB   ← 今ここ
   バンドC
 [ 前に戻す ]  [ 次のバンドへ ▶ ]
───────────────────────
癒し系ミュージシャン ・中庭
 ブロック1 14:00〜14:40 （閉じている。タップで開く）
```

- 日付タブ。今日があれば今日
- 時間内のブロックを開いた状態で上に出す。それ以外は閉じて時刻順
- 「次のバンドへ」は大きく緑（#00B894）。「前に戻す」は白地の枠ボタン
- 押したらすぐ画面に反映（useOptimistic）。失敗したら元に戻し、エラー文を出す
- ブロックが終了（出演者数 + 1）なら「このブロックは終了しました」と出し、「次のバンドへ」は押せない
- 時間外のブロックでも押せる（リハーサルや開始前の準備のため）。ただし「時間外なので来場者には演奏中と表示されません」と小さく出す

### 管理者のみ: 番組表の編集（同じページの下、または「編集」切り替え）

- セクションの追加・編集・削除（名前・場所・並び順）
- ブロックの追加・編集・削除（開始・終了。日時は JST で入力し +09:00 で送る、今のライブ追加と同じ）
- 出演者の追加・編集・削除（名前・紹介文・写真の URL）、上下ボタンで並べ替え
- 削除は確認ダイアログ。セクション・ブロックの削除は「中の出演者もすべて消えます」と赤で出す

## 7. モック

`db/init/03-seed.sql` と `db/seed/stage.sql` に、2 日分のモックを入れる。

- 10/31: Live1（第一体育館、1 ブロック 8 バンド）、癒し系ミュージシャン（中庭、2 ブロック × 3 組）
- 11/1: Live2（第一体育館、1 ブロック 6 バンド）、弾き語り（中庭、3 ブロック × 2 組）

## 8. テスト

- バックエンド: domain（current_order の上下限、時刻の検証、now_playing の判定を時刻を渡して）、repository（入れ子での取得、CASCADE、move）、handler（権限 403、404、400）、e2e（追加 → next → GET /stage で now_playing）
- フロント: 日付への振り分け・演奏中の帯・印・終わったセクションの判定を `src/lib/stage-schedule.ts` の純粋関数にして vitest。Server Action（next/prev/編集）は既存の ops.test.ts と同じ方法
- 実機確認: Playwright（インストール済み Chrome、390px）で来場者画面と学生会画面

## 9. 進め方

1. バックエンド: スキーマ・domain・repository・usecase・handler・モック → PR
2. フロント: 来場者画面（/stage-event） → 学生会の操作 → 管理者の編集 → PR

バックエンドの PR が先にマージされている必要がある。
