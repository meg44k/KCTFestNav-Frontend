# 混雑度に「準備中」を足す 設計

- 作成日: 2026-10-07
- 対象リポジトリ: KCTFestNav-Backend(値の決まり・未設定の扱い)、KCTFestNav-Frontend(来場者画面・地図・管理画面)
- 期限: 高専祭(2026-10-31〜11-01)の 1 週間前、10/24 まで

## 1. 目的

今の混雑度は「空き / 少し混雑 / 混雑」の 3 段階で、まだ一度も設定していないブースは「空いています」と出る。開場前や準備の途中でも「空いています」と出て、来場者が行ってしまう。
混雑度に **「準備中」** を足し、**灰色** で表す。

成功の基準:
- 企画担当が混雑度を一度も押していないブースは、来場者に「準備中」と灰色で出る
- 企画担当と学生会が、管理画面から「準備中」に切り替えられる
- 来場者の一覧・地図・カードで、準備中が空きと見分けられる

## 2. 決定事項(本人と合意済み 2026-10-07)

- 値は **3 = 準備中** を足す。0(空き)・1(少し混雑)・2(混雑)はそのまま
- まだ一度も設定していないブースは **準備中** として返す(今は空き)
- 日をまたぐときに自動で準備中に戻す仕組みは作らない(企画担当が各自で切り替える)
- 色は灰色 `#9CA3AF`
- ことばは来場者の画面も運営の画面も **準備中 / すぐ入れる / 少し待つ / かなり待つ**(2026-10-07 本人の希望で変更。`CONGESTION_LABELS` 1 か所)。一覧の絞り込みは「すぐ入れる展示/バザー」、並び順は「待ち時間順」。以下の本文の「空き」「混雑度順」などは、このことばに読み替える
- 準備中のブースは「更新が止まっている」扱いにしない(赤い「混雑度を更新してください」を出さず、件数にも数えず、「更新が古い順」では後ろ)

## 3. バックエンド

- `domain.BoothCongestionPreparing CongestionStatus = 3` を足す
- `ValidateCongestionLevel` は 0〜3 を受け付ける(4 以上・負は今までどおりエラー → 400)
- repository の `GetByID`・`GetAll` で、Redis に混雑度が無いとき(`redis.Nil`)は **準備中(3)** を返す(今は空き)
- 混雑度を更新する API(`PATCH /manage/booths/:id/congestion`)は 3 を受け付ける。権限は今までどおり
- `docs/openapi.yaml` の congestion_status の説明に 3 = 準備中 を足す
- 既存の Redis の値は触らない(設定済みのブースはその値のまま)

## 4. フロント

### 4.1 型と変換(`src/lib/api/booths.ts`)

- `CongestionStatus` に `"preparing"` を足す
- `toCongestionStatus`: 3 → `"preparing"`。**知らない値は `"preparing"`**(今は `"empty"`。分からないときに「空いています」と言わない)

### 4.2 来場者の画面

- **ブースのカード**(`BoothCard`): 準備中は見出しのタブと枠を灰色、文言「準備中です」
- **一覧**(`booth-browser.ts`):
  - 「空いている展示/バザー」の絞り込みは空きだけ(準備中は含めない。今の `=== "empty"` のまま)
  - 「混雑度順」は 空き → 少し混雑 → 混雑 → 準備中(準備中は最後)
  - 準備中のブースには「○分前に更新」を出さない
- **地図**: ピンは灰色(`PIN_COLORS.preparing`)。左下の凡例に「準備中」を足す

### 4.3 管理画面

- 色と名前の一覧 `CONGESTION_LEVELS`(`src/lib/manage/congestion.ts`)に `{ value: 3, label: "準備中", color: "#9CA3AF" }` を足す。企画担当の混雑度ボタン(`CongestionButtons`)と学生会の監視(`CongestionMonitor`)はこの一覧から作っているので、ボタンと表示が増える
- ボタンの並びは 準備中 → 空き → 少し混雑 → 混雑(開場の流れの順)
- 学生会の監視の「混んでいる順」(`ops.ts`)は今 `congestion_status` の数の大きい順なので、3 が混雑より上に来てしまう。**混雑 → 少し混雑 → 空き → 準備中** の順にする
- 管理者のブース一覧(`BoothList`)の混雑度の表示も準備中を灰色で出す

### 4.4 移る間

- フロントだけ先に新しくなりバックエンドが古いと、未設定のブースは 0 が返るので今までどおり「空いています」。壊れはしない
- バックエンドを先にマージし、Redis はそのまま(未設定のブースだけ準備中になる)

## 5. テスト

- バックエンド: domain(3 を受け付ける、4 と -1 はエラー)、repository(Redis に無いときは 3)、e2e(PATCH で 3 を保存して GET で 3、4 は 400)
- フロント:
  - `toCongestionStatus`(3 → preparing、知らない値 → preparing)
  - 一覧の並び(準備中が最後)、絞り込み(準備中は「空いている」に入らない)
  - 学生会の監視の「混んでいる順」(準備中が最後)
  - 地図のピンの混雑度(準備中)
- 実機: Playwright(390px)でカード・地図のピンと凡例・企画担当の「準備中」ボタン・学生会の監視

## 6. 進め方

1. バックエンド: 値・未設定の扱い・テスト・openapi → PR
2. フロント: 型と変換 → カード・一覧・地図 → 管理画面 → PR

バックエンドの PR を先にマージする。
