# キャンパスマップ（/map） 設計

- 作成日: 2026-10-07
- 対象リポジトリ: KCTFestNav-Frontend（地図・管理画面・ブース詳細）、KCTFestNav-Backend（ブースに階を足す）
- 期限: 高専祭（2026-10-31〜11-01）の 1 週間前、10/24 まで

## 1. 目的

来場者が会場のどこに何があるかを地図で分かるようにする。

- クラス展示は建物の中にあるので、**3D で棟と階、その階の中の具体的な場所**まで分かる
- クラブバザーは屋外で上下に重ならないので、**2D の平面図**で分かる
- 自分が今どこにいるか（現在地と向き）が地図の上で分かる

成功の基準:
- 入口ページの「マップ」から開くと、校舎全体の 3D にすべてのブースのピンが立っている
- ブースのカードの「場所を見る」から開くと、その棟が色付きになり、その階より上が半透明になって、ピンが見える
- 管理者が管理画面で地図を押すだけでブースの場所と階を登録できる

## 2. 決定事項（本人と合意済み 2026-10-07）

- `/map` は 3D と 2D の両方を持ち、切り替えられる。最初は 2D で全体、ピンはすべて(2026-10-07 本人の希望で 3D から変更。建物の中のブースを「場所を見る」で開くときだけ 3D)
- 絞り込み「すべて / クラス展示 / クラブバザー」。クラブバザーを選ぶと 2D に切り替わる（切り替えボタンで戻せる）
- 2D は校舎の形だけのシンプルな図（航空写真・一般の地図は使わない）
- 3D で棟だけでなく具体的な場所まで分かるようにする
- ブースの場所は管理者が地図を押して置く。加えて「今いる場所を入れる」ボタン
- 現在地（と向き）を地図に出す。道案内はしない
- バックエンドのブースに「階」を足す。既存の `x / y / z` 列は**残して使わない**（後で消すか決める）
- 道案内（棟の入口まで導く等）は今回作らない

## 3. データ

### 3.1 キャンパスの形

- `campus-3d/campus.geojson`（viewer.html で書き出したもの）を `src/data/campus.json` としてフロントに入れる。API には載せない（棟が変わるのは年 1 回程度で、ファイルの差し替えで足りる）
- 1 Feature = 建物の 1 部分。使う properties:
  - `buildingId`（統合した部分は共通）、`buildingName`（無い棟は名前なし）
  - `height`（PLATEAU の実測、m。null のことがある）、`heightUsed`（viewer で使った高さ）
  - `storeysManual`（本人が入れた階数）、`storeys`（PLATEAU の階数）
  - `baseHeight`（渡り廊下など浮いた部分の下端、m）
- 棟の**高さ**: 実測 `height` があればそれ、無ければ `heightUsed`。体育館（実測 11.7m・1 階）のような天井の高い建物を低くしないため
- 棟の**階数**: `storeysManual` > `storeys` > 1
- 階の帯の高さ = 部分の高さ ÷ 階数。統合した棟は部分ごとに計算する
- 名前の無い棟（倉庫・渡り廊下など 27 棟）は灰色の箱として描き、ラベルは出さない

### 3.2 ブースの階（バックエンド）

```sql
ALTER TABLE booths ADD COLUMN floor INT NOT NULL DEFAULT 0;
```

- `floor`: 0 = 屋外（または未設定）、1 以上 = その階
- どの棟にあるかは保存しない。ブースの緯度・経度を含む建物の形から求める（点が建物の中か、の判定）
- 管理者用のブース作成・更新 API に `floor` を足す（0 以上の整数。負は 400）。一覧・詳細の応答にも `floor` を足す
- `x / y / z` はそのまま（使わない）

## 4. /map の画面

```
[≡]                                   ← いつものメニュー
[すべて] [クラス展示] [クラブバザー]   ← 絞り込み(URL ?type= に残す)
┌──────────────────────────┐
│                                  │
│        3D の校舎とピン             │
│                                  │
│                         [現在地]  │
│                         [ 2D ]   │  ← 2D/3D 切り替え(今の MapTypeToggle を使う)
└──────────────────────────┘
```

- 画面いっぱいに地図。タイトル「マップ」は出さない（地図を広く使う）
- 絞り込みと 2D/3D は URL に残す（`/map?type=club&view=2d`）
- ピンを押すと、下に小さなカード（ブース名・場所の文字・混雑度）。カードを押すとそのブースの詳細ダイアログ（今の BoothCard のダイアログを流用）
- 棟を押すと、下からその棟のブース一覧（階ごとに並べる）。一覧のブースを押すとそのブースを選んだ状態（§5）に
- 何も無い所を押すと選択を外す
- 位置が未設定（緯度・経度が 0）のブースはピンを出さない

### 4.1 3D

- three.js。viewer.html と同じく、建物は形を押し出した単色の箱。地面は無地（航空写真は使わない。軽さと見た目のため）
- 操作は回転・拡大・移動（OrbitControls、指 1 本で回転、2 本で拡大・移動）
- 名前のある棟の上にラベル
- ピン: ブースの位置の、その階の床の高さに立てる（屋外は地面）。色はクラス展示とバザーで分ける

### 4.2 2D

- SVG。黒地に校舎の形（名前のある棟は少し明るく）と棟の名前、ピン
- 指で拡大・移動できる
- 建物の中のブース（階 ≥ 1）のピンには「2F」のように階を添える

## 5. ブースを選んだ状態（3D で具体的な場所を見せる）

- そのブースの棟だけ色を付け、ほかの棟はグレー
- その棟の、選んだ階より上の部分を半透明にする（床の上のピンが見える）
- 選んだ階を帯で目立たせ、「3号館 2F」と出す
- カメラをその棟に寄せる
- 2D では、その棟を色付きにしてピンを大きくする

## 6. 現在地

- 右下の「現在地」ボタンを押すと、位置情報（と向き）の許可を求め、青い点と向きの扇形を出す。押すまでは許可を求めない
- 向きは既存の `useCompass` と同じ方法（iOS は `requestPermission`、`webkitCompassHeading`）。取れなければ点だけ
- 誤差は点のまわりの円で表す
- 会場（建物全体の範囲 + 100m）の外なら「会場の外にいます」と出し、点は出さない
- 何階にいるかは分からないので、点は地面の高さに出す
- 拒否されたら「位置情報が使えません。設定から許可してください」と出す

## 7. 管理画面でブースを置く

ブースの作成・編集ダイアログ（`BoothFormDialog`）に地図を足す。

- 2D の地図（§4.2 と同じ描き方）を出し、押した所にピンを置く
  - 押した所が建物の中なら「3号館（4階建て）」と出し、階を 1〜階数から選ぶ（初期値 1）
  - 外なら「屋外」として階は 0
- 「今いる場所を入れる」ボタン: 位置情報で緯度・経度を入れ、精度「±○m」を出す。30m より悪ければ「誤差が大きいので地図で確かめてください」と出す。建物の中の判定と階の選び方は地図を押したときと同じ
- 緯度・経度の数字の欄は、細かい直し用に「数字で入力」として折りたたんで残す
- 保存すると `latitude`・`longitude`・`floor` を送る

## 8. ブース詳細から開く

- BoothCard のダイアログに「場所を見る」を足す（位置が設定されているブースだけ）。`/map?booth=ID` へ
- `/map?booth=ID` は、そのブースを選んだ状態（§5）で開く。屋外（階 0）のブースは 2D で開く
- ID のブースが無い・位置が無いときは、選ばずに全体で開く

## 9. 作り方

- `/map` はサーバーでブース一覧を取り（`apiFetch`、60 秒ごとに更新）、地図は Client Component
- three.js は `/map` と管理画面の地図でだけ読み込む（`next/dynamic`、`ssr: false`）。他の画面を重くしない
- 計算は純粋関数にして vitest で確かめる（`src/lib/map/`）:
  - 経緯度 ↔ メートル（viewer と同じ平面近似）
  - 点が建物の中か（どの棟か）
  - 棟の高さ・階数・各階の床の高さ
  - 会場の範囲内か
  - ブース → 地図上の位置（x, 床の高さ, z）
- 描画（three.js・SVG）は Playwright（インストール済み Chrome、390px）で確かめる

## 10. テスト

- 純粋関数（§9）: 統合した棟・切り分けた棟・浮いた部分（渡り廊下）・穴のある形・建物の外の点・階数の無い棟・体育館（実測が高い 1 階建て）
- バックエンド: `floor` の保存と応答、負の値は 400、既存のブースは 0
- Server Action: ブースの保存で `floor` を送る
- 実機: `/map`（3D・2D・絞り込み・ピン・棟の一覧）、`/map?booth=ID`（クラス展示と屋外）、現在地（許可・拒否・会場の外）、管理画面で地図を押して保存

## 11. 進め方

1. バックエンド: `floor` 列・API・テスト・マイグレーション → PR
2. フロント: データと計算（`src/lib/map/`） → `/map` の 3D・2D → ブースを選んだ状態と「場所を見る」 → 現在地 → 管理画面の地図 → PR

バックエンドの PR が先にマージされている必要がある。
